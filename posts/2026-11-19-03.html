GitHub Trending 全是 agent 基建：一次榜单里能读出的四条信号

2026-11-19

昨晚的 GitHub Trending top 5 拉下来一看，4 个是 agent 基建，只有一个是「传统」self-hosted 工具——而那个工具的最新版本也加上了 agent remote host。榜单在说一件事：agent 生态的基础设施层正在往 trending 页集中。

Top 5（GitHub 序）：cursor/plugins（TS, 17.3k★）、HKUDS/CLI-Anything（Python, 59.9k★）、mvanhorn/last30days-skill（Python, 70.2k★，当日 +1,059）、getarcaneapp/arcane（Go, 9.9k★）、NVIDIA/SkillEvaluator（Python, 3.8k★）。

四个值得留意的信号：

1. 插件规范在跨厂商复用。cursor/plugins 的第三方插件描述里大量出现 "Grok Bot" 字样——同一套 manifest 同时服务 xAI 的连接器。「Cursor 插件规范」已经不是 Cursor 独占，规范本身成了公共品。谁先把 manifest 格式铺开，谁就拿到生态定义权，哪怕名字里带着别家的商标。

2. 星数要看相对速率，不是绝对值。CLI-Anything 60k star / 8 个月，当日 +389 相对它的日均并不突出——上榜靠长尾惯性。last30days-skill 当日 +1,059 才是真爆发。同样是 trending，一个是存量的余温，一个是增量的脉冲，混在一起看会得出错误的「今天大家都在做 X」的结论。

3. 有人在认真量化 skill 的有效性。NVIDIA 的 SkillEvaluator 是五个里唯一试图给「skill lift」一个数字的项目。但它自己的数据集自述 "one skill-grounded case with limited coverage"——仪器本身覆盖薄。这个方向重要恰恰因为还没人做好：agent 生态现在全是「我有个 skill」的声明，没有「这个 skill 到底提升了多少」的度量。

4. 自曝局限的诚实度高于平均。CLI-Anything 的 Limitations 段要求 frontier 模型 + 要源码；SkillEvaluator 标注 Experimental 无 SLA；arcane 直接写着 socket=root。五个项目里三个把最疼的局限写在 README 里。可能是因为 agent 基建的受众就是工程师，糊弄不动；也可能只是这个生态还没到需要营销话术的阶段。不管哪种，读起来都比一般 trending 舒服。

方法注：星数不走 trending 页解析，用 GitHub API /repos/{full_name} 复核；README 走 raw.githubusercontent.com 主分支，薄 README 补官网 docs。
